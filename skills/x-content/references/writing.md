# 写作与读者重读

## 选角度与组织内容

一条帖文或一个串集中讲一个主要意思。先找值得讲的具体发现，用事实或例子
让读者看出它为什么有意思，再决定怎样开头。

按目标读者的熟悉程度安排背景。介绍陌生产品更新时，先交代它是什么、替谁
做什么，再讲变化和影响；读者熟悉产品用途时，直接讲更新。新的功能或使用
场景仍在需要时说明，用具体动作解释。
观点、期待和示例接上前文的事情，让读者知道说的是谁的行为、回应哪个问题。

来源是素材，不是提纲。用户给出文章、英文帖文、引用、截图或发布说明时，
选择支撑主旨、帮助读者理解变化或决定怎么用的内容，其余留作背景，避免
沿原文逐段换词。原有顺序适合这次表达时可以保留。忠实翻译的请求则保留
原文意图和结构。
只有原话本身值得讨论或准确措辞很重要时才直接引用，并保留来源归属。
用户已经给出中心态度时，用具体变化解释它，不把整份 changelog 改成中文。

第一句使用素材中最有分量的事实、影响、反差或作者判断，让读者知道在说
什么，理解这句话所需的背景一起交代，其余随后文展开。可以有情绪，但情绪
不能替代事件本身。
不要套万能爆款句式、假造紧迫性和共识，或把需要后文纠正的夸张结论当作钩子。

后文持续增加信息：用具体行为、例子或关键证据解释第一句，再展开有用的
影响。值得关注的细节留足篇幅，用场景、解释或例子讲透，让读者得到具体
发现、理解、做法，也可以是共鸣或乐趣。提高密度靠选择内容，保留理解所需
的原因和关系，
不把每句话加工成金句。技术介绍先让读者看到实际影响，再按需要解释机制
和分类。

个人感受、体验、吐槽和随手发现，围绕作者在意的事情展开，用具体经历、
反应和判断带出意思。新闻可以用事实接作者判断，技术观点用具体使用或
工作流支撑，回复和评论直接回应对方当前那句话。讨论点从事实和取舍中长出来，不靠结尾补
你怎么看。实用信息、解释和共鸣都能独立成立，不必改成教程或购买建议。
话说完就结束，删掉没有新增信息的总结和升华。前文已经说明的取舍或条件，
也不用再写成一句提醒。

## 证据与限定

用户明确确认或实测过的结果，按给定范围写，不因助手没查到官方文档就
改回似乎；若与可靠证据冲突，在成稿外说明具体冲突。

正文保留与主题有关且有依据的内容，助手的检索过程放在成稿外。作者本来
要分享的调查或实测经历按原意保留。

来源归属、时间、实验条件和适用范围按当前主张取舍，保留省略后会使读者
误解这项变化或结论的关键条件，并放在对应事实旁边。
已交代清楚的限定或免责声明，不要在每段或每楼结尾反复补充。

## 单帖、串和素材

按用户要求和可用的发布形式，根据内容选择短单帖、长单帖或串。一个发现
几句能讲清就短写，需要背景、例子或分析就充分展开；内容适合连续阅读时
用长单帖，有适合分楼承接的层次时写串。篇幅服务于内容，不预设越短越好，
也不把长内容自动拆成串。

- 主帖独立交代事件、具体影响或判断和必要背景。会改变主帖含义的关键
  限定留在主帖，不能等读者点开跟帖后才纠正第一印象。
- 跟帖承接证据、机制、分类、路径、例外和来源，不重写一遍主帖，也不按
  固定条数拆分。偏离主线的发现可以另发。
- 首楼需要引出后文时，可以提出下文会回答的具体问题。下一楼直接承接，
  并兑现首楼承诺；不用空泛预告或未经证实的因果关系制造悬念，也不要求
  每楼用问句收尾。修改钩子后重新检查跟帖顺序。
- 图片、截图、图表或短演示可以提供证据、展示差异、帮助理解，也可以表达
  幽默、情绪或共鸣。选择能与帖文相互补充的素材；涉及关键事实时在正文里
  交代清楚。需要另做素材时说明用途。

## 从读者视角重读

重读时只看正文，先用目标读者熟悉的话复述这条帖文讲了什么。复述依赖来源、
前面对话或超出目标读者背景的知识补出的关系，就是正文需要补足或改写的
地方。按帖文类型复述讲的事情、表达的观点或感受，以及值得关注的地方；
把理解所依赖的关系对应到正文，再顺着正文检查，尤其留意中间最密集的段落：

| 阅读位置 | 读者可能卡住的原因 | 实际修改 |
|---------|------------------|---------|
| 第一眼 | 知道产品名，却不知道它在什么场景里替谁做什么 | 把具体事实或影响提前，补足理解这个变化所需的场景 |
| 第一次出现术语或比较 | 不认识模式名，不知道这个数字和谁比较 | 先说行为和关系，只解释理解当前观点所需的术语与口径 |
| 句子内部 | 名词或限定词堆叠、背景夹在主语和动作之间，或不知道它、自己指谁 | 把动作提前，背景另接一句，换成自然的说法，写清谁做了什么 |
| 段落中间 | 连续列功能、转折太多，或反复换词说同一件事 | 重选支撑主线的材料，补连接原因，删重复，把旁支移到跟帖 |
| 段落或楼层交界 | 观点、期待或示例突然出现，不知道它接的是哪件事 | 交代说话者、对象和与前文的关系，再调整顺序 |
| 读完 | 事情列完了，值得关注的发现或感受还没展开；或已经讲透还在补结论 | 展开支撑主线的细节、解释或感受，话讲到位后自然结束 |

逐句判断它相对前文增加了什么，以及读者凭什么愿意继续。找出具体失去兴趣
或理解中断的句子并修改。疑似重复的句子先删掉试读；读者对事情、关系和
作者态度的理解没有改变，就保留删后的版本。再连着读一遍受影响的部分。
不设固定句长或段数，不靠每句话换行伪装轻松，也不为简短删掉必要背景、
解释、例子或关键条件。

例如，“系统列出重复文件，让你选择删哪份。它只负责找重复，删除仍由你
决定。”后一句没有增加内容，删掉即可。素材里出现的能力边界，也按它是否
影响当前主张取舍，而不是照单写进结尾。

用户说太复杂、像文档或读到一半读不下去时，先调整主帖的信息选择和展开
顺序，再改措辞与标点。只换开头、删几个字或保留全部分类重新排版不算解决。

## 发布格式与定稿

X 正文用可直接粘贴的文本，不依赖 Markdown 加粗、标题或带锚文本的超链接。
需要链接时给可见的完整 URL。来源按用户指定的位置放置；要求单独一楼时，
集中给来源名称和 URL，其他楼保持无链接。楼层标签与说明放在可复制正文外。

按用户指定的字数或帖文格式核对长度。

以用户最新编辑或已发布版本为准，保留语气、中心判断和主帖与评论的分工。
局部修改保留其余内容，再检查受影响的上下文，不把已经删除的检索过程或
旧措辞加回来。

成稿先完成上面的读者重读，修改后再交付。默认按最终发布顺序给出可直接
使用的完整稿，合并已确认的钩子、分楼和链接。
用户只要局部时按指定范围返回。必要说明放在正文外；点评、评分或写作过程
仅在用户要求时提供。
